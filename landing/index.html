How It Works
Three steps to encrypted secrets
No accounts, no cloud, no subscriptions. Just you and your master password.
1

Create a Vault

Set a master password. We generate a random salt and Vault Encryption Key (VEK). Your password is never stored — only the wrapped VEK is written to disk.

2

Add Secrets

Each secret gets its own Data Encryption Key (DEK), derived from your VEK + a unique record ID. Every secret is independently encrypted with XChaCha20-Poly1305.

3

Access Anywhere

Export the .enc file and move it to any machine. The file is useless without your master password. One password unlocks everything — anywhere, anytime.

Features
Built for people who take security seriously
Every design decision prioritizes confidentiality, portability, and simplicity.
🔐

Envelope Encryption

Multi-layer key hierarchy: password → Argon2id → KEK → VEK → HKDF → DEK. Compromising one layer doesn't expose the rest.

🛡️

Tamper-Proof Storage

HMAC-SHA256 integrity verification on every unlock. Any modification to the vault file is detected before decryption begins.

🧹

Memory Hygiene

All cryptographic keys, passwords, and plaintext values are zeroized in memory using the zeroize crate. Nothing lingers after use.

📋

Clipboard Auto-Clear

Secrets copied to the clipboard are automatically erased after a configurable timeout. No stale passwords in your clipboard history.

🔁

Per-Record Keys

Each secret is encrypted with its own unique key derived from HKDF-SHA256. Same value under different record IDs produces different ciphertext.

🎲

Built-in Password Generator

Generate cryptographically secure passwords with configurable length and character classes. Entropy calculation and strength scoring included.

📦

Portable .enc Format

One file. 256-byte header + encrypted records. Move it between machines, OSes, and languages. Works everywhere.

🔌

Multi-Language SDK

Use the same .enc file from Python, Node.js, Go, Java, Rust, or the CLI. One vault format, every ecosystem.

💻

CLI + Web App

Native CLI for power users and scripting. Web app (WASM) for browser use with auto-lock and search. Same crypto, different interfaces.

Security
Enterprise-grade cryptography, zero infrastructure
We use published, audited, NIST-recommended algorithms. No custom crypto, no shortcuts.
🔑

Key Derivation — Argon2id

RFC 9106 winner. Memory-hard function resistant to GPU/ASIC attacks. Configurable memory cost, time cost, and parallelism.

🔒

Encryption — XChaCha20-Poly1305

RFC 8439. 192-bit nonces (practically eliminates collision concerns). Authenticated encryption (confidentiality + integrity).

🧬

Key Derivation — HKDF-SHA256

HMAC-based Extract-and-Expand Key Derivation Function. Derives unique per-record keys from the VEK + record ID as salt.

✅

Integrity — HMAC-SHA256

Detects any modification to the vault file. Verified before every decryption. Tampered files are rejected immediately.

🧹

Memory Safety — zeroize

All sensitive data (keys, passwords, plaintexts) is explicitly zeroed in memory on drop. Prevents memory scraping after use.

🎲

CSPRNG — getrandom

Cryptographically secure random number generation via OS entropy sources. Vaults, salts, nonces — all truly random.

✅ Protected Against

  • Theft of vault file — requires master password
  • Tampering — HMAC catches modifications
  • Memory scraping — keys zeroized on exit
  • Brute-force — Argon2id is intentionally slow
  • Rainbow tables — unique 32-byte salt per vault
  • Ciphertext analysis — XChaCha20 is IND-CCA secure

⚠️ Not Protected Against

  • Keyloggers capturing the master password
  • Compromised OS reading memory while unlocked
  • Shoulder surfing during password entry
  • Forgotten master password (no recovery by design)
  • Someone with physical access while vault is unlocked
